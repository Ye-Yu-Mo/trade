# 我们做了一个能验证 LLM 交易的框架，然后发现 SMA 跑输了抛硬币

> 一个 Rust + DeepSeek 的多智能体交易框架。重点不是“能赚钱”，而是“能验证”。
>
> 仓库：https://github.com/Ye-Yu-Mo/trade

## 1. 交易机器人最不值钱的东西，是收益截图

GitHub 上的 LLM 交易项目，大多长这样：一张漂亮的净值曲线，一段“AI 自动交易”的演示视频，然后是一个需要主网 API key 才能跑起来的仓库。

你没法验证它。你不知道手续费算没算、有没有未来函数、参数是不是在全量历史上挑出来的、回撤是怎么定义的。

所以我们想做一个相反的东西：**任何人都能在 60 秒内跑出结果，并且结果可以被质疑、被复现。**

## 2. 60 秒，不需要 API key

```bash
git clone https://github.com/Ye-Yu-Mo/trade
cd trade
cargo run --release -- demo
```

它会用仓库内置的 90 天 BTCUSDT 1h 样本跑一次 SMA 回测，把结果写进 Dashboard，然后启动在 `http://127.0.0.1:8080`。

你能看到：

- 账户权益曲线和每笔成交
- 风控状态（止损 / 止盈 / 熔断）
- 最近决策与成交
- 回测结果浏览
- **Agent 决策流**：一段真实 DeepSeek 运行录制下来的多智能体决策链

Demo 不联网、不需要 key，也不假装自己赚钱。

## 3. 我们怎么避免自欺欺人

### Walk-forward，而不是“历史最优参数”

单区间回测很容易过拟合。我们把数据切成滚动的训练 / 测试窗口：

```
[warmup][train][test][train][test]...
```

训练窗口里遍历 fast/slow 参数组合，选一组；然后**只在紧接着的测试窗口上评估**。测试窗口的权益链接起来，得到样本外曲线。

多标的使用等权分配，不共享保证金，不做再平衡。

### 成本必须算

默认单边手续费 5bps，滑点 2bps。这不是可选项，是默认值。

### 风控必须是代码

很多 LLM 交易项目把风控写进 prompt：“如果亏损超过 2% 就止损”。但模型不会真的执行它。

在这个项目里，风险管理员是一个确定性函数 `risk::assess`：

- 时机评分 < 5 → 拒绝
- ATR ≥ 8% → 拒绝；≥ 5% → 仓位减半
- 策略方向与趋势相反 → 仓位减半
- 达到最大持仓 / 分配资金为零 / 低于交易所最小数量 → 拒绝

交易员的 LLM 输出之后还要过 `risk::enforce`：

- 风控 `rejected` → 强制 HOLD
- 风控 `adjusted` → 数量被截断

**LLM 可以提出意图，但不能覆盖风控。**

## 4. 第一份基准结果

BTCUSDT + ETHUSDT，1h，2025-01-01 → 2025-06-01，train 720 / test 240，手续费 5bps + 滑点 2bps，随机种子 42：

| Strategy | Portfolio | Buy & hold | Max DD | Sharpe | Trades | Win rate | Fees |
|---|---:|---:|---:|---:|---:|---:|---:|
| SMA walk-forward | -7.42% | +2.86% | 7.54% | -2.28 | 422 | 33.4% | 404.31 |
| Random (p=0.05) | +0.17% | +2.86% | 4.18% | 0.11 | 213 | 41.8% | 213.36 |
| Buy & hold | +2.76% | +2.76% | 37.38% | 0.48 | 0 | — | 10.00 |

三个观察：

**1）SMA 跑输了抛硬币。** 不是“策略不够好”，而是 422 笔交易、404 USDT 手续费——在 10000 USDT 本金上，光手续费就吃掉了 4%。高频反手在 1h 级别上很难覆盖成本。

**2）买入持有收益最高，但回撤 37%。** 收益和风险必须一起看。随机基线的回撤只有 4.18%，虽然收益几乎为零。

**3）walk-forward 会把“历史最优”打回原形。** 如果你在单区间上挑参数，很容易得到漂亮曲线；换到下一段没见过的数据，优势就消失了。

这个结果对我们来说不是坏消息，而是产品的一部分：**如果一个框架只能产出好消息，它大概率在骗你。**

## 5. 让 Agent 的决策过程可见

LLM 交易最不透明的地方是：你只看到 BUY / SELL，不知道它为什么。

`trade analyze` 会跑一次完整决策链，但不下单：

```bash
cargo run --release -- analyze --symbol BTCUSDT --interval 1h
```

真实输出（2026-11-06 的一次运行）：

```
[1/4] 行情分析员 (1477ms, 4419 tokens): Bearish / Strong / Markdown
      放量破位下跌，均线空头排列，价格创新低，处于下跌阶段，反弹乏力。
[2/4] 策略研究员 (1355ms, 1236 tokens): OpenShort | 时机 8/10
[3/4] 风险管理员（代码）: Low | 审批 Approved | 建议 0.026
[4/4] 决策交易员 (1012ms, 1327 tokens): Sell | 信心 High
```

每一步都会写入 `logs/agent_trace.jsonl`：模型、是否命中缓存、耗时、prompt/completion tokens、完整 JSON 输出。Dashboard 里可以直接展开看。

这也是我们做多智能体的真实原因：不是为了“更像人”，而是为了把决策拆成可以单独检查和替换的步骤。

## 6. 架构上的一些取舍

- **每个标的每轮 2 次模型调用**（策略 + 交易员），风控由代码完成。2 个标的时从 9 次/轮降到 7 次/轮。
- **JSON 模式 + 超时 + 重试**：默认 `response_format=json_object`，60 秒超时，解析失败会作废缓存重试一次。
- **缓存键包含模型 / base URL / 温度 / JSON 模式**：换模型不会误用旧响应。
- **交易所条件单**：开仓后挂 `STOP_MARKET` / `TAKE_PROFIT_MARKET`（`closePosition=true`），盘中由交易所触发，不完全依赖轮询。
- **显式平仓**：`CLOSE` 是独立动作，不会因为想平仓而被强制反手开空。
- **69 个单元测试**：回测撮合、风控、指标、缓存、路径安全、示例数据都有覆盖。

## 7. 局限

- 回测不模拟资金费率、保证金强平和盘口冲击；盘中止损按 K 线高低点估算。
- LLM 决策是非确定性的，同一根 K 线可能给出不同信号。
- 目前只接了 Binance USDT 本位合约。
- LLM 基准是可选功能（每个测试 bar 一次调用），本文的表格没有包含 LLM 行。
- 样本只有 6 个月、2 个标的，结论不应该被外推。
